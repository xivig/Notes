Module 01

Install Python & create a professional workspace

Use a supported Python 3 release (3.10–3.14) and isolate each project’s dependencies.

Chapter Guide (MD) →Verified Lab (lab.py) →
1.1 Install and verify Python

Install Python 3 from the official downloads page. On Windows, enable the option to add Python to PATH. On macOS/Linux, use the system package manager or the official installer appropriate to your platform.

# Check the interpreter
python --version
# Some systems use:
python3 --version

# Check pip
python -m pip --version

Use the same interpreter for pip commands: python -m pip. This avoids installing a package into a different Python installation.

1.2 Create a project and virtual environment
mkdir hello-python
cd hello-python

# Create an isolated environment
python -m venv .venv

# Windows PowerShell
.venv\Scripts\Activate.ps1

# macOS / Linux
source .venv/bin/activate

python -m pip install --upgrade pip

A virtual environment keeps project dependencies isolated cleanly. Add .venv/ to .gitignore; never commit it. For modern fast workflows, consider uv: uv init, uv add httpx pytest, uv run main.py.

1.3 Your first program and editor workflow
# hello.py
def main() -> None:
    name = input("What is your name? ").strip()
    if not name:
        name = "Python learner"
    print(f"Hello, {name}! Welcome to Python.")

if __name__ == "__main__":
    main()
python hello.py

Use an editor with Python language support, linting, formatting and debugging. Learn the terminal, file navigation, Git basics and how to read tracebacks early.

Syntax, variables & data types

Names, values, expressions, strings, numbers, booleans, None and type conversion.

2.1 Names, assignment and Python's dynamic typing

Python is dynamically typed, but variables still refer to objects with types. Prefer descriptive snake_case names. Constants are conventionally written in UPPER_SNAKE_CASE.

# A name refers to an object; Python infers the type at runtime
display_name = "Ada"
age = 36
height_m = 1.68
is_learning = True
nothing_here = None

print(type(display_name).__name__)  # str
print(type(age).__name__)           # int
print(f"{display_name} is {age}")

3.1 if / elif / else

Conditions are evaluated from top to bottom; the first matching branch runs. Keep conditions simple and extract complicated decisions into named functions.

Iterate over values directly when you do not need an index. Use enumerate when you need both an index and an item.

3.3 while, break, continue and loop else

break exits the nearest loop; continue skips to the next iteration. A loop's else clause runs only if the loop finishes normally (without break).

attempts = 0
while attempts < 3:
    attempts += 1
    if attempts == 2:
        continue
    print("Attempt", attempts)
else:
    print("Loop completed without break")

3.4 match / case

Structural pattern matching is available in Python 3.10+. Use it when matching structured values or alternative shapes makes code clearer than nested conditionals.

command = "start"

match command:
    case "start":
        result = "Starting"
    case "stop":
        result = "Stopping"
    case "restart":
        result = "Restarting"
    case _:
        result = "Unknown command"

print(result)

# Structural pattern matching on dictionaries + guards (Python 3.10+)
event = {"type": "click", "x": 12, "y": 40}
match event:
    case {"type": "click", "x": int(x), "y": int(y)} if x >= 0:
        print(f"Click at ({x}, {y})")

4.1 Lists and slicing

Lists are ordered and mutable. Assignment does not copy a list: use list.copy() or scores[:] for a shallow copy. Nested mutable objects are still shared by a shallow copy.

scores = [72, 91, 84]
scores.append(96)
scores.extend([67, 88])

print(scores[0])       # first item
print(scores[-1])      # last item
print(scores[1:4])     # slice: start included, stop excluded
print(scores[::-1])    # reversed copy

scores.sort()
print(scores)

Module 05

Functions & reusable design

Parameters, return values, scope, closures, lambda, type hints and documentation.

5.1 Define functions and return values

A function should have one clear responsibility. Prefer returning values over printing inside reusable business logic. Defaults are evaluated once at function definition time; avoid mutable defaults such as [].

# Always use None sentinel for mutable defaults (never items=[])
def add_tag(tag: str, tags: list[str] | None = None) -> list[str]:
    out = [] if tags is None else list(tags)
    out.append(tag.strip().lower())
    return out

def calculate_total(price: float, quantity: int = 1) -> float:
    """Return the total before tax."""
    if price < 0 or quantity < 0:
        raise ValueError("price and quantity must be non-negative")
    return price * quantity

total = calculate_total(12.5, quantity=3)
print(total)

The slash marks positional-only parameters; the bare asterisk marks keyword-only parameters. *args collects extra positional arguments; **kwargs collects extra keyword arguments.

        "roles": roles,
        "active": active,
        "metadata": metadata,

5.3 Scope, closures and lambda

Python resolves names using the LEGB rule: Local, Enclosing, Global, Built-in. Use lambda for small expressions, not multi-step logic.

def make_multiplier(factor: int):
    def multiply(value: int) -> int:
        return value * factor
    return multiply

double = make_multiplier(2)
print(double(9))

names = ["zoe", "Ada", "linus"]
print(sorted(names, key=lambda name: name.lower()))

8.1 Exceptions and cleanup

Catch the narrowest exception you can handle. Do not silently swallow errors with a bare except. Use finally for cleanup that must happen regardless of success.

def read_age(value: str) -> int:
    try:
        age = int(value)
    except ValueError as exc:
        raise ValueError("Age must be a whole number") from exc

    if age < 0:
        raise ValueError("Age cannot be negative")
    return age

try:
    print(read_age("twenty"))
except ValueError as error:
    print("Input problem:", error)

8.2 Custom exceptions and assertions

Use custom exceptions for meaningful domain failures. assert is for developer assumptions and tests; it can be disabled and must not validate user input.

class InsufficientFundsError(Exception):
    """Raised when an account cannot cover a withdrawal."""

def withdraw(balance: float, amount: float) -> float:
    if amount <= 0:
        raise ValueError("amount must be positive")
    if amount > balance:
        raise InsufficientFundsError("not enough funds")
    return balance - amount

assert withdraw(100, 30) == 70

9.1 Classes, instances and methods

self refers to the current instance. A leading underscore signals a non-public implementation detail by convention; it is not strict access control.

class BankAccount:
    def __init__(self, owner: str, opening_balance: float = 0):
        self.owner = owner
        self._balance = opening_balance

    @property
    def balance(self) -> float:
        return self._balance

    def deposit(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError("amount must be positive")
        self._balance += amount

account = BankAccount("Mina", 100)
account.deposit(25)
print(account.balance)

9.2 Inheritance, composition and dataclasses

Prefer composition when one object uses or contains another. Inheritance models a genuine 'is-a' relationship. dataclasses reduce boilerplate for data-centric classes.

from dataclasses import dataclass

@dataclass(frozen=True, slots=True)
class Product:
    name: str
    price: float
    in_stock: bool = True

@dataclass
class Cart:
    items: list[Product]

    def total(self) -> float:
        return sum(item.price for item in self.items)

cart = Cart([Product("Book", 250), Product("Pen", 20)])
print(cart.total())

9.3 Dunder methods and protocols

Special methods such as __repr__, __len__, __iter__ and __eq__ integrate objects with Python syntax and built-ins. Design behavior around clear protocols.

class Temperature:
    def __init__(self, celsius: float):
        self.celsius = celsius

    def __repr__(self) -> str:
        return f"Temperature({self.celsius!r})"

    def __eq__(self, other):
        if not isinstance(other, Temperature):
            return NotImplemented
        return self.celsius == other.celsius

print(Temperature(20))

10.1 Iterators and generators

An iterable can produce an iterator; an iterator yields one item at a time. Generators are lazy and useful for streams or large datasets.

def fibonacci(limit: int):
    a, b = 0, 1
    while a < limit:
        yield a
        a, b = b, a + b

for value in fibonacci(100):
    print(value)

10.2 Decorators

A decorator takes a callable and returns a callable. functools.wraps preserves useful metadata. Decorators are useful for logging, authorization, caching and instrumentation.

from functools import wraps
from time import perf_counter

def measure_time(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            elapsed = perf_counter() - start
            print(f"{func.__name__}: {elapsed:.4f}s")
    return wrapper

@measure_time
def calculate():
    return sum(range(100_000))

calculate()

10.3 Context managers

Context managers define setup/teardown behavior through __enter__/__exit__ or a contextmanager generator. Use them for files, locks, transactions and temporary state.

from contextlib import contextmanager

@contextmanager
def managed_resource():
    print("acquire")
    try:
        yield "resource"
    finally:
        print("release")

with managed_resource() as resource:
    print("using", resource)

Type hints document intent and enable static analysis; Python does not enforce them automatically at runtime. Use a type checker such as mypy or pyright for larger projects.

    connection.execute(

15.1 AsyncIO coroutines

async def defines a coroutine; await suspends it until an awaitable completes. AsyncIO is most useful for many concurrent I/O operations, not automatically for CPU-heavy work.

import asyncio

async def fetch(label: str, delay: float) -> str:
    print("starting", label)
    await asyncio.sleep(delay)  # placeholder for async I/O
    return f"done: {label}"

async def main():
    results = await asyncio.gather(
        fetch("A", 1),
        fetch("B", 0.5),
    )
    print(results)

if __name__ == "__main__":
    asyncio.run(main())

15.2 Threads and processes

Threads are commonly useful for blocking I/O. Processes can use multiple CPU cores for CPU-bound tasks. Measure performance and account for synchronization and serialization costs.

from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

def square(number: int) -> int:
    return number * number

numbers = [1, 2, 3, 4]

with ThreadPoolExecutor() as pool:
    io_style_results = list(pool.map(square, numbers))

16.1 Secure coding basics

Do not hard-code secrets. Validate and constrain untrusted input, use least privilege, keep dependencies patched, use TLS, and avoid unsafe deserialization (for example, never unpickle untrusted data).

# Validate input at trust boundaries.
def safe_filename(name: str) -> str:
    if not name or "/" in name or "\\" in name:
        raise ValueError("invalid filename")
    return name

Guided build sequence: task manager

Use this as your first complete project. Build one milestone at a time; do not copy the entire solution before understanding each step.

Milestone 1 — Define the task model

Decide what a task contains: a unique integer ID, title, completion status and creation timestamp. Write down valid and invalid inputs.

from dataclasses import dataclass
from datetime import datetime, timezone

@dataclass
class Task:
    id: int
    title: str
    done: bool = False
    created_at: str = ""

    @classmethod
    def create(cls, task_id: int, title: str):
        title = title.strip()
        if not title:
            raise ValueError("Task title cannot be empty")
        timestamp = datetime.now(timezone.utc).isoformat()
        return cls(task_id, title, False, timestamp)
Milestone 2 — Add storage

Write a repository module that loads a JSON list and saves it safely. Handle a missing file separately from invalid JSON. Keep storage logic out of the user interface.

Milestone 3 — Implement use cases

Create functions to add, list, complete and delete tasks. Each function should have a clear input and return value. Validate task IDs and avoid duplicated business logic.

Milestone 4 — Build the CLI

Use argparse or a simple command loop. Keep prompts and printing in the CLI layer; keep task rules in service functions so they can be tested independently.

Milestone 5 — Test and document

Test empty titles, missing IDs, corrupted storage, duplicate IDs and normal operations. Add a README with installation, examples and limitations.

Language

Glossary

Core terms used throughout the handbook.

Argument / parameter

An argument is supplied at a call site; a parameter is a name in a function definition.

Iterable / iterator

An iterable can provide an iterator; an iterator yields values one at a time.

Mutable / immutable

Mutable objects can be changed in place; immutable objects cannot be changed after creation.

Exception

An object representing an error or unusual condition during execution.

Module / package

A module is a Python source file; a package organizes modules under a namespace.

Decorator

A callable that takes another callable and returns a callable, commonly extending behavior.

Coroutine

An asynchronous computation that can suspend and resume, commonly using async and await.

Environment

A Python interpreter plus installed dependencies and configuration used to run a project.
