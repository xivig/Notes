Unlike Windows, which assigns drive letters (C:, D:) to individual storage partitions, Unix organizes everything beneath a single inverted tree rooted at / (the root directory). Devices, network shares, memory buffers, and files all mount into this unified namespace.

CHAPTER 7 / SHELL EXPANSION MECHANICS

Globbing, quoting and expansion

Master how the shell parses lines: brace expansion, tilde expansion, parameter expansion, command substitution, word splitting, and globbing order.

Understanding the exact sequence in which the shell evaluates an input line before passing arguments to a command prevents countless bugs and subtle security flaws.

The 7-Stage Shell Evaluation Order

  1. Brace Expansion: {a,b,c}, {1..10} expands into discrete tokens.
  2. Tilde Expansion: ~ expands to $HOME.
  3. Parameter & Variable Expansion: $VAR, ${VAR:-default} replaces values.
  4. Command Substitution: $(command) executes subshell and captures stdout.
  5. Arithmetic Expansion: $(( 5 * 20 )) evaluates integer math.
  6. Word Splitting: Unquoted expansions are split into words on characters in $IFS.
  7. Pathname Expansion (Globbing): *, ?, [...] match filesystem paths.

Quoting Rules Comparison

Quoting StyleSyntaxBehavior & Expansions
Single Quotes'text $VAR'Literal: All characters preserved literally. No expansions or substitutions occur.
Double Quotes"text $VAR"Interpolated: Allows $VAR, $(cmd), and $((math)), but disables word splitting and globbing.
ANSI C Quoting$'line1\nline2\t'Interprets backslash escape sequences (\n newline, \t tab, \xHH hex).
Unquotedtext $VAR *Dangerous: Subject to word splitting on spaces and wildcards matching files.
Cardinal Rule of Shell Variables: Always wrap variable references in double quotes: "$VAR". This prevents filenames containing spaces or tabs from being split into multiple arguments! 
# Brace expansion patterns
echo file_{A,B,C}.txt            # file_A.txt file_B.txt file_C.txt
echo {01..10}                    # 01 02 03 04 05 06 07 08 09 10
echo {a..z..2}                   # a c e g i k m o q s u w y (step by 2)

# Command substitution (modern $() vs legacy backticks)
backup_file="backup-$(date +%F).tar.gz"  # Preferred: readable and nestable
legacy_file="backup-`date +%F`.tar.gz"   # Avoid: backticks are difficult to nest

# Extended Globbing in Bash (turn on with: shopt -s extglob)
# ?(pattern) = 0 or 1 match; *(pattern) = 0 or more; +(pattern) = 1 or more
# !(pattern) = matches everything EXCEPT the pattern
rm -f !(*.jpg|*.png)  # Deletes all files EXCEPT .jpg and .png images

Control read, write, execute bits, understand octal notation, configure SUID/SGID/sticky bits, calculate umask, and master hard vs. symbolic links.

Hard Links vs Symbolic (Soft) Links:
  • Hard Link (ln target link): Creates a new directory entry pointing to the exact same inode number. Cannot cross filesystem boundaries or link directories. Deleting the original file keeps the data intact until all hard links are removed.
  • Symbolic Link (ln -s target link): Creates an independent file containing a text path pointing to the target. Can span across filesystems and point to directories. If target is deleted, link becomes broken ("dangling").
# Modify permissions symbolically
chmod u+rwx,g+rx,o-rwx script.sh   # User rwx, group rx, others none

# Modify permissions with octal numbers
chmod 750 script.sh                # User=7 (rwx), Group=5 (r-x), Others=0 (---)
chmod 644 config.json              # Standard read-write for owner, read-only for all

# Change user and group ownership recursively
sudo chown -R www-data:www-data /var/www/html

# Apply Sticky Bit to a directory
chmod 1777 /var/shared_scratch     # Equivalent to: chmod +t /var/shared_scratch

# Calculate umask defaults
umask                              # e.g. 0022 -> Default new files: 644, directories: 755
umask 027                          # Hardens defaults -> Files: 640, directories: 750

CHAPTER 12 / DEVELOPER FIELD GUIDE

Processes, jobs and signals

Inspect programs, control execution priority, manage foreground/background jobs, and handle signals safely.

Every running program on a Unix system is represented as a process with a unique Process ID (PID), parent process ID (PPID), user ownership, and memory space. The shell manages interactive commands as jobs.

# Process inspection
ps aux                 # Snapshot of all running processes (BSD style)
ps -ef                 # Standard System V format showing PPID hierarchy
pgrep -af nginx        # Find PIDs matching name with full command line
top                    # Interactive system monitor (or htop / btop)

# Managing shell background jobs
sleep 300 &            # Run in background; returns [job_number] PID
jobs -l                # List active background jobs with PIDs
fg %1                  # Bring job 1 to the foreground
# Press Ctrl+Z to suspend running foreground process (sends SIGTSTP)
bg %1                  # Resume suspended job 1 in background

# Decoupling from the terminal
nohup ./long-task.sh > task.log 2>&1 & # Immune to terminal hangups (SIGHUP)
disown -h %1           # Remove job from shell job table so logout won't terminate it

# Adjusting execution priority (nice levels range from -20 highest to +19 lowest)
nice -n 10 ./build.sh  # Launch CPU-heavy task with lower priority
renice +5 -p 12345     # Alter priority of an already-running process

1. If/Else Conditionals & The Strict Spacing Rule

Unlike most programming languages where spaces are largely stylistic, the Bourne shell treats spaces in an if [ ... ] statement as syntactic tokens. The opening bracket [ is not syntax; it is an alias for the command test. Therefore, arguments must be separated by spaces, and the test command must terminate with a matching ].

Every if construct must conclude with fi (the reverse of if), regardless of whether an else branch is present.

#!/bin/sh
# Security demonstration script using Bourne shell if/else
VALID_PASSWORD="secret"

echo "Please enter the password:"
read PASSWORD

if [ "$PASSWORD" == "$VALID_PASSWORD" ]; then
    echo "You have access!"
else
    echo "ACCESS DENIED!"
fi

Syntax Analysis:

  • [ "$PASSWORD" == "$VALID_PASSWORD" ]: Evaluates string equality. Notice the mandatory space after [ and before ].
  • To test if variables are not equal, replace == with !=: [ "$PASSWORD" != "$VALID_PASSWORD" ].
  • In strict POSIX sh, single = is the standard string equality operator; Bash supports both = and ==.

2. File Persistence, Stateful Flow & Command Substitution

The following script demonstrates user input handling, file existence testing, and reading/writing state to disk. It prompts for a username; if a data file named username_DAT exists and is not empty (using the -s operator), it reads and displays the stored age. If the file does not exist, it prompts for the user's age, validates acceptable boundaries, and writes the age to disk.

#!/bin/sh
# Interactive age validation and file persistence

# Prompt for a username...
echo "Please enter your name:"
read USERNAME

# Check if the persistence file exists and is not empty (-s)
if [ -s ${USERNAME}_DAT ]; then
    # Read the age from the file using command substitution
    AGE=`cat ${USERNAME}_DAT`
    echo "You are $AGE years old!"
else
    # Ask the user for his/her age
    echo "How old are you?"
    read AGE

    if [ "$AGE" -le 2 ]; then
        echo "You are too young!"
    else
        if [ "$AGE" -ge 100 ]; then
            echo "You are too old!"
        else
            # Write the validated age to a new file
            echo $AGE > ${USERNAME}_DAT
        fi
    fi
fi

Walkthrough of the 4 Execution Scenarios:

  • Run 1 (Underage): Enter name john, age 1. Condition "$AGE" -le 2 matches; script prints "You are too young!" and exits without saving.
  • Run 2 (Overage): Enter name john, age 200. Condition "$AGE" -ge 100 matches; script prints "You are too old!" and exits.
  • Run 3 (Valid age): Enter name john, age 30. Script enters the inner else branch, executes echo $AGE > john_DAT, creating file john_DAT containing 30.
  • Run 4 (Persistent recall): Enter name john. Condition [ -s john_DAT ] evaluates to true! The script skips the age prompt entirely, reads the age from disk, and outputs "You are 30 years old!".

Understanding Command Substitution:

The expression AGE=`cat ${USERNAME}_DAT` captures the stdout of cat into variable AGE. While backticks were the historical Bourne standard, modern shell scripts use AGE=$(cat "${USERNAME}_DAT") for nesting capability and clearer readability.

5. Key Engineering Modernizations for Developers

  • Always quote variables: Use [ "$AGE" -le 2 ] instead of [ $AGE -le 2 ]. Unquoted variables cause syntax crashes when empty.
  • Upgrade from expr to $(( ... )): Modern shells perform integer math internally in C without launching slow external subshells.
  • Upgrade from backticks to $(...): Backticks (`command`) cannot be nested easily and obscure escaping. Use $(cat file).
  • Prefer [[ ... ]] in Bash: For Bash scripts, use double brackets [[ ... ]] instead of [ ... ] to eliminate word-splitting bugs and gain native regex matching.
  • Secrets handling: The original password check in unix examples.txt embeds passwords in plain text. For production systems, use environment variables, hashes, or secret managers.
