01. Chapter 01 — PHP 8.3–8.5 Syntax, Strict Types & Null Safety for Laravel

Modern Laravel (Laravel 12 & 13) requires PHP 8.2/8.3+ and embraces strict typing, scalar/union/intersection types, nullsafe operators, and concise control flow. Mastering these core syntax primitives prevents subtle type coercion bugs across models, requests, and services.

1. Strict Types & Scalar Type Declarations

Without declare(strict_types=1);, PHP silently coerces "42" into 42 when passed to an int parameter, or 1 into true. Enable strict typing at the top of custom service classes, Actions, DTOs, and helpers:

PHP
<?php

declare(strict_types=1);

namespace App\Services;

final class DiscountCalculator
{
    public function applyPercentage(int $cents, float $rate): int
    {
        return (int) round($cents * (1 - $rate));
    }
}

Type System Essentials Used Daily in Laravel

  • Scalar & Compound: int, float, string, bool, array, callable, iterable, object
  • Union Types (|): int|string|null $id (very common for Eloquent IDs vs UUIDs)
  • Intersection Types (&): Countable&IteratorAggregate
  • Return Types: void, never (functions that always throw or abort()), self, static (fluent builders like Eloquent scopes), mixed
  • Standalone true / false / null (PHP 8.2+): function fails(): bool vs returning false explicitly on failure paths

2. Ternary ?:, Elvis ?:, Null Coalescing ?? & Nullsafe ?->

In Blade templates, requests, and user profiles, nullable chains happen constantly. Know the exact difference between each operator:

OperatorChecksExampleBehavior if left is "" or 0
$a ? $b : $cTruthiness ((bool) $a)$active ? 'Yes' : 'No'Uses $c
$a ?: $bTruthiness shorthand (Elvis)$title ?: 'Untitled'Uses 'Untitled'
$a ?? $bisset() (!= null and defined)$perPage ?? 15Keeps "" or 0!
$a ??= $bNull coalescing assignment$options['timeout'] ??= 30;Keeps 0 or false
$obj?->propShort-circuits if $obj === null$user?->profile?->avatarEvaluates to null instead of throwing Error

Laravel Blade & Auth Example

PHP
// Safe navigation even when Auth::user() is null or has no profile row
$avatarUrl = Auth::user()?->profile?->avatar_url ?? '/images/default-avatar.png';

// Elvis operator when empty strings should also fall back:
$displayName = trim((string) $request->input('nickname')) ?: 'Anonymous Author';
Warning: Do not chain $a?->b = 'x' on write assignments — PHP forbids the nullsafe operator on the left side of an assignment (=).

3. Constants, Read-Only Data & Named Arguments

Laravel 12/13 heavily uses named arguments for readable configuration (Route::resource(...)->only([...]), factory states, Http::retry(times: 3, sleepMilliseconds: 200)):

PHP
function paginateQuery(int $page = 1, int $perPage = 15, string $sort = 'desc'): array
{
    return compact('page', 'perPage', 'sort');
}

// Skip optional defaults cleanly by name:
$params = paginateQuery(perPage: 25, sort: 'asc');

PHP 8.3 also introduced typed class constants, which catch mismatched overrides in subclasses:

PHP
abstract class ApiResponder
{
    public const string VERSION = 'v2';
}

Key Takeaways

  • Put declare(strict_types=1); in custom classes, DTOs, Actions, and Value Objects.
  • Use ?? when preserving 0, "", or false matters; use ?: when empty strings or zeroes should fall back.
  • Combine ?-> with ?? for clean, crash-free property traversal in controllers and Blade templates.

02. Chapter 02 — OOP, Inheritance, Magic Methods & Lifecycle

Every Eloquent Model, Controller, FormRequest, Job, and Event in Laravel builds directly on PHP object-oriented fundamentals: class hierarchies, multi-level inheritance aliases, late static binding (static::), and magic methods (__get, __set, __call, __toString).

1. Aliasing & Multi-Level Inheritance in Laravel

When you open app/Models/User.php in a fresh Laravel project, you immediately see aliasing paired with multi-level inheritance:

PHP
use Illuminate\Foundation\Auth\User as Authenticatable;

class User extends Authenticatable
{
    // ...
}

Why as Authenticatable Exists

Because the framework base class is already named User (Illuminate\Foundation\Auth\User), importing both would cause a name collision in App\Models\User. Aliasing it with as Authenticatable resolves the conflict and clarifies its role.

The Real Inheritance Chain Under the Hood

  1. App\Models\User extends Illuminate\Foundation\Auth\User
  2. Illuminate\Foundation\Auth\User extends Illuminate\Database\Eloquent\Model
  3. Therefore App\Models\User inherits both authentication contracts (Authorizable, Authenticatable) and all Eloquent ORM methods (save(), where(), relations).

2. parent::, self::, static:: & Late Static Binding

Eloquent relies heavily on static:: (Late Static Binding) so helper methods defined in a parent class (Model::query(), Model::create()) return instances of the called subclass (Post, User), not the base Model:

PHP
abstract class BaseModel
{
    public static function tableName(): string
    {
        return static::$table; // Resolves late to the calling child class
    }

    public static function make(): static
    {
        return new static();
    }
}

final class Post extends BaseModel
{
    protected static string $table = 'posts';
}

echo Post::tableName(); // "posts"
  • self:: binds at compile time to the class where the method is written.
  • static:: binds at runtime to whichever subclass is invoked.
  • parent:: explicitly calls the overridden implementation in the immediate superclass (for example parent::__construct()).

3. Magic Methods Behind Eloquent & Blade

Have you wondered how $post->title works when Post has no public $title property, or how User::whereEmail(...) works? Eloquent intercepts property and method access with PHP magic methods:

4. Object Cloning, Identity (===) & Value Equality

In PHP, assigning $b = $a copies the object handle, meaning both variables mutate the exact same instance:

  • Use clone $a to create a shallow duplicate (implement __clone() if nested objects must also be deep-cloned).
  • In PHP 8.5+, clone($obj, ['status' => 'published']) simplifies immutable with*() updates on readonly classes.
  • $a === $b checks whether both variables point to the same instance; $a == $b compares class + property values. Eloquent provides $user->is($otherUser) to compare primary key, table, and connection safely.

Key Takeaways

  • class User extends Authenticatable uses a use ... as ... import alias to build a clean multi-level hierarchy on top of Eloquent\Model.
  • Prefer static:: (and : static return type) when writing reusable factory or query methods on base classes.
  • Understanding __get, __set, __isset, and __callStatic demystifies Eloquent attributes, dynamic scopes, and Facades.

abstract class MiniModel
{
    protected static string $table = 'base';

    /** @var array<string, mixed> */
    protected array $attributes = [];

    /** @var array<string, bool> */
    protected array $dirty = [];

    /** @param array<string, mixed> $attributes */

    {
        $this->attributes = $attributes;
    }

    public static function tableName(): string
    {
        return static::$table;
    }

    /** @param array<string, mixed> $attributes */
    public static function create(array $attributes): static
    {
        return new static($attributes);
    }

    public function __get(string $key): mixed
    {
        return $this->attributes[$key] ?? null;
    }

    public function __set(string $key, mixed $value): void
    {
        $this->attributes[$key] = $value;
        $this->dirty[$key] = true;
    }

    public function __isset(string $key): bool
    {
        return isset($this->attributes[$key]);
    }

    public function isDirty(?string $key = null): bool
    {
        return $key === null ? $this->dirty !== [] : ($this->dirty[$key] ?? false);
    }

    public function __toString(): string
    {
        return json_encode([
            'table' => static::tableName(),
            'attributes' => $this->attributes,
        ], JSON_THROW_ON_ERROR);
    }
}

{
    public function canLogin(): bool

        return (bool) ($this->attributes['is_active'] ?? true);

}

    protected static string $table = 'users';

03. Chapter 03 — Interfaces, Traits, Visibility & Contracts

Because PHP enforces single class inheritance, a model or controller can only extend one parent class. Laravel and packages like Filament or Spatie solve this cleanly by pairing abstract base classes, interfaces (contracts), and traits (horizontal code reuse).

1. Single Inheritance + Traits (extends + use Trait)

In Eloquent, a model inherits ORM behavior from Model, then stacks reusable capabilities via Traits:

PHP
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\SoftDeletes;

class Post extends Model
{
    use HasFactory;
    use SoftDeletes;
}

How Laravel Automatically Boots Traits (bootTraitName)

Any trait defining public static function bootTraitName() is automatically discovered and invoked when Eloquent boots the model — zero boilerplate inside your class! For example, SoftDeletes registers a global scope via bootSoftDeletes() so queries automatically add WHERE deleted_at IS NULL.

2. extends + implements (The Integration Contract)

When integrating admin panels, authorization gates, or domain services, you often implement an interface contract alongside inheritance:

PHP
use Filament\Models\Contracts\FilamentUser;
use Filament\Panel;
use Illuminate\Foundation\Auth\User as Authenticatable;

class User extends Authenticatable implements FilamentUser
{
    public function canAccessPanel(Panel $panel): bool
    {
        return str_ends_with($this->email, '@yourdomain.com')
            && $this->hasVerifiedEmail();
    }
}
  • Interface (implements): Guarantees a strict method signature contract at compile time.
  • Class (extends): Inherits state and default behavior from one parent.

3. The "Contract + Trait" Architecture Pattern

Libraries like Spatie Media Library pair an interface with a trait:

PHP
use Spatie\MediaLibrary\HasMedia;
use Spatie\MediaLibrary\InteractsWithMedia;

class Product extends Model implements HasMedia
{
    use InteractsWithMedia;
}
  1. Why require the Interface? Type-hinting function processUpload(HasMedia $entity) lets services verify the object supports media operations without coupling to a concrete model class.
  2. Why provide the Trait? InteractsWithMedia satisfies the dozens of methods declared in HasMedia automatically, keeping Product concise.

4. Abstract Classes vs Interfaces + Trait Composition in Controllers

An abstract class defines shared state or base implementations for closely related subclasses, while traits mix cross-cutting helpers cleanly:

PHP
trait ApiResponse
{
    protected function success(mixed $data, string $message = 'OK', int $status = 200): array
    {
        return ['status' => $status, 'message' => $message, 'data' => $data];
    }
}

abstract class Controller
{
    use ApiResponse;
}

final class OrderController extends Controller
{
    public function show(int $id): array
    {
        return $this->success(['order_id' => $id]);
    }
}

5. Visibility (public, protected, private) & Property Rules

KeywordAccessible FromLaravel Rule of Thumb
publicAnywhere (routes, views, tests, container)Route action methods (index, store), Service interfaces, constants
protectedDefining class + child classes (Model)$fillable, $hidden, casts(): array, controller helper methods
privateDefining class only (hidden from subclasses)Internal service helpers that children must NOT rely on or override
Important: Critical Eloquent & Routing Gotchas
- Laravel's Model reads $fillable, $guarded, $table, and casts() from a parent/base context — declaring them private hides them from Eloquent! Always keep Eloquent configuration protected.
- Controller route methods (index, show, store) MUST be public so Laravel's router can invoke them; mark internal helper methods inside controllers protected or private so they are never mistaken for routable endpoints.
- Visibility Widening: A subclass may widen visibility (protected -> public), never narrow it (public -> protected).

Key Takeaways

  • Use Traits for horizontal reuse (SoftDeletes, HasFactory, ApiResponse) and Interfaces to enforce contracts.
  • Combine implements Contract + use HelperTrait whenever building extensible packages or domain behaviors.
  • Keep route controller actions public and Eloquent properties ($fillable, casts()) protected.

trait InteractsWithMediaTrait

        return 'Booted media hooks cleanly';
    }

    public function addMedia(string $path): void
    {
        $this->mediaItems[] = $path;
    }

    public function getMedia(): array
    {
        return $this->mediaItems;
    }
}

trait ApiResponseTrait
{
    /** @param array<string, mixed> $data */
    protected function successResponse(array $data, string $message = 'OK'): array
    {
        return ['ok' => true, 'message' => $message, 'data' => $data];
    }
}

abstract class BaseModel
{
    /** @var list<string> */
    protected array $fillable = [];

    /** @return list<string> */
    public function getFillable(): array
    {
        return $this->fillable;
    }

    public static function bootTraits(): array
    {
        $messages = [];
        foreach (class_uses_recursive(static::class) as $trait) {
            $short = basename(str_replace('\\', '/', $trait));
            $method = 'boot' . $short;
            if (method_exists(static::class, $method)) {
                $messages[] = static::$method();
            }
        }
        return $messages;
    }
}

function class_uses_recursive(string|object $class): array
{
    $results = [];
    foreach (array_reverse(class_parents($class) ?: []) + [$class => $class] as $parent) {
        $results += class_uses($parent) ?: [];
    }
    return array_values(array_unique($results));
}

{
    use InteractsWithMediaTrait;

    /** @var list<string> */
    protected array $fillable = ['name', 'price_cents'];
}

{
    use ApiResponseTrait;

    public function uploadDemo(HasMediaContract $entity, string $file): array
    {
        $entity->addMedia($file);

        return $this->successResponse([
            'fillable' => $entity instanceof BaseModel ? $entity->getFillable() : [],
            'media' => $entity->getMedia(),
        ], 'Uploaded');
    }
}

04. Chapter 04 — Modern PHP (8.0–8.5): Enums, Attributes, Property Hooks & Pipe

Laravel 12 requires PHP >= 8.2 (supporting 8.3–8.5) and Laravel 13 (March 2026) requires PHP >= 8.3 and natively embraces PHP Attributes, Backed Enums, Constructor Promotion, match, and readonly DTOs.

1. Constructor Property Promotion & readonly Classes (PHP 8.0–8.2)

Instead of declaring properties, parameters, and $this->x = $x three times, promote constructor arguments directly:

PHP
final readonly class CreateOrderData
{
    public function __construct(
        public int $userId,
        public int $totalCents,
        public string $currency = 'USD',
    ) {}
}

Marking the entire class readonly (PHP 8.2+) automatically makes every promoted property immutable — ideal for Data Transfer Objects (DTOs), Service responses, and Value Objects passed into Laravel Actions.

2. match Expression & Backed Enums (PHP 8.0–8.1)

Unlike switch, match compares with strict identity (===), needs no break, returns a value directly, and throws UnhandledMatchError if a case is missed:

PHP
enum OrderStatus: string
{
    case Pending = 'pending';
    case Paid = 'paid';
    case Shipped = 'shipped';

    public function badgeColor(): string
    {
        return match ($this) {
            self::Pending => 'amber',
            self::Paid => 'emerald',
            self::Shipped => 'indigo',
        };
    }
}

Eloquent Enum Casting

In Laravel models, define casts(): array so $order->status automatically hydrates into an OrderStatus instance:

PHP
protected function casts(): array
{
    return [
        'status' => OrderStatus::class,
    ];
}

3. PHP Attributes (#[...]) — Core to Laravel 13

Attributes attach structured metadata to classes, methods, or properties — inspectable at runtime via ReflectionClass::getAttributes().

While PHP 8.0 introduced attributes and Laravel has supported #[ObservedBy] / #[ScopedBy] on models, Laravel 13 expanded first-class PHP Attributes across Models, Jobs, Commands, FormRequests, and Policies:

PHP
use Illuminate\Database\Eloquent\Attributes\Fillable;
use Illuminate\Database\Eloquent\Attributes\Hidden;
use Illuminate\Database\Eloquent\Attributes\Table;

#[Table(name: 'posts')]
#[Fillable(['title', 'slug', 'body', 'published_at'])]
#[Hidden(['internal_notes'])]
final class Post extends Model
{
    // Replaces property boilerplate cleanly when preferred
}

On queued Jobs and Commands in Laravel 13:

PHP
#[Tries(5)]
#[Timeout(120)]
#[Connection('redis')]
final class ProcessInvoiceJob implements ShouldQueue

    // ...

4. PHP 8.3 Highlights

  • Typed class constants: public const string ROLE_ADMIN = 'admin';
  • #[Override] attribute: Tells PHP to fail at compile/load time if a parent method signature changes and your subclass no longer overrides anything!
  • json_validate(string $json): Validates JSON syntax without allocating decoded arrays in memory.

5. PHP 8.4 Highlights (When Running PHP >= 8.4)

  • Property Hooks: Native get and set interceptors on properties, replacing boilerplate getters/setters:
PHP
  final class EmailAddress
  {
      public string $value {
          set => strtolower(trim($value));
      }
  }
  • Asymmetric Visibility: public private(set) string $slug; — readable anywhere, writable only inside the class.
  • Chaining new without outer parentheses: (new Pipeline())->send($x) can now be written new Pipeline()->send($x).
  • New Array Finders: array_find(), array_find_key(), array_any(), array_all().

6. PHP 8.5 Highlights (When Running PHP >= 8.5)

  • Pipe Operator (|>): Passes left-hand value into a right-hand unary callable cleanly from top to bottom:
PHP
  $slug = '  Hello Laravel 13!  '
      |> trim(...)
      |> strtolower(...)

  • clone($object, ['status' => 'published']): Concise immutable updates for readonly DTOs and models.
  • #[NoDiscard] attribute, array_first(), and array_last().

Key Takeaways

  • Use readonly class DTOs + Constructor Promotion to pass validated data safely from FormRequests into Actions/Services.
  • Combine Backed Enums with match + Eloquent casts(): array to eliminate magic strings.
  • Use #[Override] (PHP 8.3+) and Laravel 13 Attributes (#[Fillable], #[Tries]) for cleaner, type-checked metadata.

05. Chapter 05 — Closures, Exceptions, Arrays & Strings for Laravel

Day-to-day Laravel development spends far more time transforming Collections, extracting request keys, formatting slugs, capturing closures in routes/transactions, and handling exceptions than writing raw SQL. 1. Closures, use (...) & Arrow Functions (fn =>)

In Laravel, routes, query constraints, Collections, and database transactions all accept anonymous functions:

PHP

$adults = $users->filter(function ($user) use ($minAge) {
    return $user->age >= $minAge;
});

// 2. Arrow function (`fn`): auto-captures outer variables by value, single expression
$names = $users
    ->filter(fn ($user) => $user->age >= $minAge)

// 3. First-class callable syntax (PHP 8.1+): pass method or function reference cleanly
$trimmed = array_map(trim(...), $rawInputs);

Inside Laravel Transactions & Routes

PHP

DB::transaction(function () use ($order, $payment) {

2. Exception Handling (try / catch / finally) & bootstrap/app.php

PHP 8+ separates runtime errors (Error, e.g., DivisionByZeroError, TypeError) from application exceptions (Exception), unified under the common Throwable interface.

PHP
try {
    $response = $gateway->charge($order);
} catch (PaymentDeclinedException $e) {
    // Handle expected business error first (specific before general!)
    return back()->withErrors(['payment' => $e->getMessage()]);
} catch (Throwable $e) {
    report($e); // Log to Sentry / storage/logs/laravel.log
    return response()->json(['message' => 'Unexpected payment failure'], 500);
} finally {
    // Always executes (e.g., release a file lock or temp resource)
}

Centralized Exception Handling in Modern Laravel (11 / 12 / 13)

Modern Laravel configures custom exception reporting and JSON rendering inside bootstrap/app.php rather than app/Exceptions/Handler.php:

PHP
->withExceptions(function (Exceptions $exceptions) {
    $exceptions->render(function (DomainException $e, Request $request) {

4. Native String Functions (PHP 8+) & Laravel Str

Modern PHP includes str_contains(), str_starts_with(), and str_ends_with(), which Laravel's Str and fluent Stringable (Str::of(...)) build upon:

PHP
$slug = Str::of('  Laravel 13 Developer Guide!  ')
    ->trim()
    ->lower()
    ->slug(); // "laravel-13-developer-guide"

Common string utilities in PHP 8.3+:

  • trim($str) / ltrim / rtrim: Sanitize form input before storage.
  • str_contains($haystack, $needle): Case-sensitive substring check (Str::contains($str, ['a', 'b']) adds multi-needle & case-insensitivity options).
  • substr($str, 0, 100): Byte-based slice — use mb_substr() or Str::limit($text, 100) for UTF-8 text (emojis, non-ASCII scripts) so characters are never cut mid-codepoint!
  • preg_match($pattern, $subject, $matches): Extract hashtags, mentions, or semantic versions with regex.

Key Takeaways

  • Use fn ($x) => ... for concise one-line transforms and function () use ($var) for multi-statement callbacks like DB::transaction().
  • Catch specific exceptions before Throwable, and register global API error mappings inside bootstrap/app.php ->withExceptions().
  • Prefer mb_substr() / Str::limit() over substr() when truncating user-submitted UTF-8 content.

06. Chapter 06 — Composer PSR-4, Service Container Auto-Wiring & Facades

Understanding how Laravel wires classes together automatically removes almost all framework "magic." Every route controller constructor injection, Service Provider binding, and Route::get(...) / Cache::remember(...) Facade call is powered by three plain-PHP pillars: PSR-4 autoloading, Reflection-based Dependency Injection, and __callStatic Facade proxies.

1. Composer PSR-4 Autoloading & Auto-Discovery

Open composer.json in any Laravel application:

JSON
{
    "autoload": {
        "psr-4": {
            "App\\": "app/",

}

How Class Paths Resolve Automatically

Because "App\\" maps directly to app/, PHP's Composer autoloader maps namespace segments 1-to-1 with folders and .php filenames:

  • App\Models\Post -> app/Models/Post.php
  • App\Http\Requests\StoreTaskRequest -> app/Http/Requests/StoreTaskRequest.php

Package Auto-Discovery (extra.laravel)

When you run composer require spatie/laravel-permission, Laravel reads the package's composer.json during composer dump-autoload (via php artisan package:discover):

JSON
"extra": {
    "laravel": {
        "providers": [
            "Spatie\\Permission\\PermissionServiceProvider"
        ]
    }
}

Laravel registers those providers automatically — zero manual editing in config files needed.

2. Static Methods vs Service Container Auto-Wiring

Many beginners confuse Route::get(...) with plain static utility methods. Here is the key architectural distinction:

Static Utilities vs Dependency Injection (DI)

  • Stateless Utility: TaxCalculator::rate() — takes inputs, returns value, holds no dependencies. Hard-calling static methods from inside services makes swapping implementations during tests hard.
  • Container Auto-Wiring (DI): When you type-hint a dependency in a controller constructor or route method:
PHP
final class CheckoutController extends Controller
{
    public function __construct(
        private readonly PaymentGatewayInterface $gateway,
    ) {}
}

Laravel does NOT literally run new CheckoutController(). Instead, its Service Container uses PHP's ReflectionClass:

  1. Inspects __construct(...) parameters.
  2. Sees PaymentGatewayInterface -> looks up any bound concrete class (e.g., StripeGateway), or recursively instantiates concrete classes like OrderMailer.
  3. Checks StripeGateway's own constructor, resolves its dependencies (zero-config auto-wiring), and passes the graph into new CheckoutController($gateway).

3. How Laravel Facades Work (__callStatic + Container)

Look inside Illuminate\Support\Facades\Cache or Route: they do NOT contain static business logic! Every Facade is a thin static proxy implementing getFacadeAccessor():

PHP
// Conceptual flow when you call Cache::get('home_stats'):
// 1. __callStatic('get', ['home_stats']) runs on Facade base class.
// 2. Resolves container instance: app()->make(static::getFacadeAccessor()) -> CacheManager
// 3. Invokes $instance->get('home_stats').
// 4. Bonus: In tests, Cache::shouldReceive('get') swaps the container instance cleanly!

That is why Facades give you clean syntax (Mail::to(...), Queue::fake()) without sacrificing testability.

Key Takeaways

  • Match namespaces and directory paths strictly under app/ so Composer's PSR-4 autoloader never misses a class.
  • Prefer constructor Dependency Injection (__construct(private readonly Service $svc)) for application services so classes remain decoupled and easy to mock or swap.
  • Remember that Laravel Facades are Container-backed __callStatic proxies, which is why Queue::fake(), Http::fake(), and Mail::fake() work seamlessly in tests.

declare(strict_types=1);

/**
 * Chapter 06 Lab: Mini Reflection Auto-Wiring Service Container + Facade Proxy.
 * Demonstrates exactly how Laravel resolves constructors and forwards Facade::method() calls.
 */

final class MiniContainer
{
    /** @var array<string, string|callable> */
    private array $bindings = [];

    /** @var array<string, object> */
    private array $instances = [];

    public function bind(string $abstract, string|callable $concrete): void
    {
        $this->bindings[$abstract] = $concrete;
    }

    public function singleton(string $abstract, string|callable $concrete): void
    {
        $this->bind($abstract, function (self $c) use ($abstract, $concrete): object {
            if (!isset($this->instances[$abstract])) {
                $this->instances[$abstract] = is_callable($concrete)
                    ? $concrete($c)
                    : $c->build($concrete);
            }
            return $this->instances[$abstract];
        });
    }

    public function swap(string $abstract, object $fake): void
    {
        $this->instances[$abstract] = $fake;
        $this->bindings[$abstract] = static fn (): object => $fake;
    }

    public function make(string $abstract): object
    {
        if (isset($this->instances[$abstract])) {
            return $this->instances[$abstract];
        }
        $concrete = $this->bindings[$abstract] ?? $abstract;
        if (is_callable($concrete)) {
            return $concrete($this);
        }
        return $this->build($concrete);
    }

    private function build(string $className): object
    {
        $reflector = new ReflectionClass($className);
        if (!$reflector->isInstantiable()) {
            throw new RuntimeException("Class {$className} is not instantiable (bind an interface to a concrete class).");
        }

        $constructor = $reflector->getConstructor();
        if ($constructor === null) {
            return new $className();
        }

        $dependencies = [];
        foreach ($constructor->getParameters() as $param) {
            $type = $param->getType();
            if ($type instanceof ReflectionNamedType && !$type->isBuiltin()) {
                $dependencies[] = $this->make($type->getName());
                continue;
            }
            if ($param->isDefaultValueAvailable()) {
                $dependencies[] = $param->getDefaultValue();
                continue;
            }
            throw new RuntimeException("Cannot resolve parameter \${$param->getName()} of {$className}.");
        }

        return $reflector->newInstanceArgs($dependencies);
    }
}

5. Eager Loading (with()) vs the N+1 Query Trap

Never access $post->author->name inside a @foreach loop without eager loading!

PHP

$posts = Post::with(['author:id,name', 'tags:id,name'])
    ->published()
    ->latest('published_at')
    ->paginate(10);

Golden Rule of Laravel: NEVER edit files inside vendor/ directly — composer update will immediately wipe out your changes! Instead, Laravel offers three clean extension seams: Container Rebinding (AppServiceProvider), Configuration & View Publishing (vendor:publish), and Inheritance Overrides.

1. Service Providers: register() vs boot()

Open app/Providers/AppServiceProvider.php:

final class AppServiceProvider extends ServiceProvider
{
    // Phase 1: ONLY bind interfaces/services into the Service Container.
    // Do NOT resolve other services, routes, or DB models here!
    public function register(): void
    {
        $this->app->bind(
            \VendorPackage\Contracts\InvoiceFormatter::class,
            \App\Services\CustomInvoiceFormatter::class
        );
    }

    // Phase 2: All providers are registered; safe to configure Eloquent, Gates, Macros, Views.
    public function boot(): void
    {
        Model::shouldBeStrict(! app()->isProduction());
    }
}

3. .env vs config() & the Production env() Rule

Caution: NEVER call env('MY_KEY') outside files inside config/*.php!
Once you run php artisan config:cache in production, Laravel merges all config files into one cached PHP array and stops reading .env files — so any env() call inside a controller or service returns null!

Always map environment variables cleanly inside config/services.php (or a custom config/billing.php) and read them via config():

PHP
// config/billing.php
return [
    'stripe_key' => env('STRIPE_KEY'),
    'currency' => env('BILLING_CURRENCY', 'USD'),
];

// Anywhere in controllers, services, or Blade:
$currency = config('billing.currency');

Key Takeaways

  • Put Container bindings in register() and runtime framework hooks (Model::shouldBeStrict(), Gates, View composers) in boot().
  • Prefer scoped() over singleton() for request-specific state if you ever deploy with Laravel Octane.
  • Always read config values through config('file.key'), never direct env() calls inside application code.

final class ConfigRepository
{
    /** @param array<string, mixed> $items */
    public function __construct(private array $items) {}

    public function get(string $dotKey, mixed $default = null): mixed
    {
        $segments = explode('.', $dotKey);
        $cursor = $this->items;
        foreach ($segments as $segment) {
            if (!is_array($cursor) || !array_key_exists($segment, $cursor)) {
                return $default;
            }
            $cursor = $cursor[$segment];
        }
        return $cursor;
    }
}

final class ProviderContainer
{
    /** @var array<string, callable> */
    private array $bindings = [];
    /** @var array<string, object> */
    private array $singletons = [];

    public function bind(string $abstract, callable $factory): void
    {
        unset($this->singletons[$abstract]);
        $this->bindings[$abstract] = static fn (self $c): object => $factory($c);
    }

    public function singleton(string $abstract, callable $factory): void
    {
        $this->bindings[$abstract] = function (self $c) use ($abstract, $factory): object {
            return $this->singletons[$abstract] ??= $factory($c);
        };
    }

    public function make(string $abstract): object
    {
        return ($this->bindings[$abstract])($this);
    }
}

2. Eloquent API Resources (JsonResource) — Never Expose Raw Models

Returning return Post::all(); directly leaks internal columns (user_id, timestamps, private flags) and couples API consumers to your DB schema. Always transform models through an API Resource:

BASH
php artisan make:resource PostResource
PHP
<?php

declare(strict_types=1);

namespace App\Http\Resources;

use Illuminate\Http\Request;
use Illuminate\Http\Resources\Json\JsonResource;

final class PostResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id' => $this->id,
            'title' => $this->title,
            'slug' => $this->slug,
            // Only serialize author when relationship was eager-loaded (prevents N+1!):
            'author' => $this->whenLoaded('author', fn () => [
                'id' => $this->author->id,
                'name' => $this->author->name,
            ]),
            'published_at' => $this->published_at?->toIso8601String(),
        ];
    }
}

Controller usage:

PHP
public function index()
{
    $posts = Post::with('author:id,name')->published()->paginate(15);

    return PostResource::collection($posts);
}

PostResource::collection($paginator) automatically includes data, links, and meta pagination metadata!

4. Consuming External APIs with Http & Http::pool()

14. Chapter 14 — Queues, Jobs, Events, Caching, `defer()` & Scheduler

Production Laravel apps never make users wait 5 seconds on an HTTP request while sending emails, resizing images, calling AI models, or generating PDFs. Instead, offload slow work using defer(), Queues (ShouldQueue), Events, Cache, and Scheduled Tasks.

1. Quick In-Request Offloading with defer() (Laravel 12 / 13)

Need to run lightweight work (analytics ping, audit log, webhook notification) right after the HTTP response flushes — without configuring a background worker yet? Use defer():

PHP
use function Illuminate\Support\defer;

Route::post('/orders', function (StoreOrderRequest $request) {
    $order = Order::create($request->validated());

    defer(fn () => Metrics::recordOrder($order->id));

    return to_route('orders.show', $order);
});

For heavy, retryable work (mail, PDF generation, third-party billing webhooks), always use Queued Jobs instead.

4. Caching (Cache::remember, flexible, & Laravel 13 Cache::touch)

Stop re-running expensive dashboard aggregations on every page view:

PHP
use Illuminate\Support\Facades\Cache;

// Cache-Aside Pattern: compute once, store for 10 minutes
$stats = Cache::remember('dashboard.stats', now()->addMinutes(10), function () {
    return [
        'published_posts' => Post::published()->count(),
        'active_users' => User::whereNotNull('email_verified_at')->count(),
    ];
});

// Stale-While-Revalidate (Cache::flexible): serve stale data 5..10 min while refreshing after response!
$feed = Cache::flexible('blog.featured', [300, 600], fn () => Post::published()->take(5)->get());

// Laravel 13: extend TTL of a cached key (without reading/overwriting payload!)
Cache::touch('user.session.prefs.' . $user->id, now()->addHours(2));

Always remember to invalidate caches (Cache::forget('dashboard.stats')) inside a Model Observer or Service when underlying records change.
